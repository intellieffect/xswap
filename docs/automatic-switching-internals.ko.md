# 자동 전환 내부 동작: 환경변수·래핑·PATH

[README](../README.ko.md#대화-중-자동-계정-전환-실험적-앱--대화형-cli)의 「대화 중 자동 계정 전환」 절이 요약만 하는 세 가지 — `codex` 심볼릭 링크 래핑과 PATH 해석, 그리고 실제 Codex 실행 파일 재배치 — 를 자세히 다룹니다.

## `codex` 래핑과 PATH 해석

구현은 데스크톱의 `CODEX_CLI_PATH`, CLI의 `--remote unix://` 연결과 App Server의 실험적 `chatgptAuthTokens` 인터페이스를 사용합니다. 앱 바이너리/설치 파일은 수정하지 않습니다. 이 인터페이스들의 호환성이 바뀔 수 있으며, 오류 시 자동 모드가 중단됩니다. `--wrap-codex`는 사용자 소유 심볼릭 링크만 교체합니다. xswap 밖에서 연결이 풀리는 경우는 두 가지입니다. Codex 업데이트(TUI의 ctrl+u, `codex upgrade`, 설치 스크립트)는 이 링크를 새 릴리스로 되돌리고, Codex 설치는 PATH에서 래핑된 항목보다 앞에 두 번째 `codex`를 추가할 수 있습니다(standalone 설치 스크립트는 `~/.local/bin/codex`를 만듭니다. 2026-09-10에 이 항목이 래핑된 `/opt/homebrew/bin/codex`를 가렸습니다). 자동 전환이 켜져 있으면 다음 `xswap` 실행, `xswap list`/`usage`, `xswap use`/`switch`가 둘 다 복구합니다. 되돌려진 링크는 `xswap-codex`로 다시 연결하고 새 릴리스를 실제 Codex로 기록하며, 래핑된 항목 앞에 새로 생긴 사용자 소유 `codex` 심볼릭 링크도 래핑해 xswap이 실행하는 항목으로 삼습니다(이전 항목은 `auto.json`의 `wrappers`에 보관). 업데이트를 실행한 브리지 세션도 종료 시 복구합니다. `xswap doctor`는 PATH의 모든 `codex`를 검사해 첫 항목이 `xswap-codex`가 아니면 FAIL(항목·대상·다음 실행에서 복구되는지 표시. 일반 파일이나 다른 사용자 소유 링크는 절대 바꾸지 않음), 래핑된 항목 뒤에 전체 경로로만 실행되는 다른 `codex`가 있으면 WARN을 표시하고, `xswap use`도 선택이 우회될 때 같은 내용을 출력합니다. `xswap auto-disable`은 래핑된 모든 항목을 현재 릴리스로 되돌립니다. 프로젝트가 자체적으로 설치한 `codex`는 xswap이 스스로 래핑하지 않습니다. npm은 `@openai/codex` 의존성에 대해 `node_modules/.bin/codex`를 만들고 그 디렉터리는 절대 경로로 PATH에 오를 수 있는데(direnv, Makefile, IDE 작업), 그 상태에서 일반적인 xswap 명령 하나가 레포지토리 안의 링크를 고쳐 쓰고 주 레코드로 삼았습니다. 이런 항목은 `project-dependency`로 보고하고 두 가지 선택지(래핑된 항목보다 앞에 있는 그 디렉터리를 PATH에서 빼거나, 그 셸에서 `auto-enable --wrap-codex`로 직접 래핑)를 안내하며, xswap 자신은 프로젝트의 파일 대신 기록된 Codex를 실행합니다. 다른 설치본의 `xswap-codex`(프로젝트 venv, uv 옆의 pipx)에 도달하는 항목도 연결된 것으로 봅니다 — 같은 `auto.json`을 읽는 같은 진입점을 실행하기 때문입니다 — 그리고 이를 실제 Codex로 기록하지 않습니다. 기록하면 일반 `codex`가 `xswap-codex`를 실행하고 그것이 다시 자신을 실행하는 무한 루프가 됩니다. PATH는 xswap을 실행한 셸의 것이며 launchd·cron 작업은 자기 PATH를 봅니다. xswap은 확신할 수 없는 항목은 고쳐 쓰지 않습니다: 링크 대상이 없거나 실행 파일이 아니거나, 항목이 일반 파일이거나 없거나 다른 사용자 소유이거나, 기록된 `xswap-codex`가 사라졌거나(xswap을 다른 위치에 다시 설치한 경우), 자동 전환이 꺼져 있으면 항목을 그대로 두고 `xswap doctor`와 `xswap use`/`switch`가 어느 경우인지와 수동 조치 방법을 알려줍니다(`xswap auto-status`에는 `wrapperReason`으로 표시됩니다). 상대 경로 PATH 항목(프로젝트의 `bin`, direnv 습관)으로 찾은 `codex`도 래핑하거나 되돌려 쓰지 않습니다 — 디렉터리마다 다른 파일을 가리키기 때문입니다. `xswap auto-enable --wrap-codex`는 현재 디렉터리의 그 파일을 래핑하지 않고 거부합니다. `xswap-codex`를 상대 경로 PATH 항목으로 찾은 경우에도 같은 이유로 거부합니다 — 기록된 proxy는 모든 디렉터리에서 래핑된 항목이 가리키는 대상이므로 절대 경로 파일 하나여야 합니다. 그래도 그 디렉터리에서는 일반 `codex`가 그 항목을 실행하므로, 보고만 하는 모든 표면이 명령을 실행한 디렉터리 기준으로 이를 알립니다: `xswap doctor`는 FAIL로 보고하고 해당 PATH 항목을 절대 경로로 바꾸라는 조치를 알려주며, `xswap auto-status`는 `codexWrapped: false`와 `wrapperReason: relative-path-entry`를 보고하고, `xswap use`/`switch`는 그 항목을 명시하며 xswap이 래핑할 수 없다고 알립니다. 빈 PATH 항목도 같은 항목입니다 — POSIX는 이를 작업 디렉터리로 읽으므로 `./codex`로 보고합니다. `~` 항목은 반대 경우입니다. `sh`와 `bash`는 조회 전에 이를 확장하므로 `PATH="~/bin:..."`(따옴표로 묶은 export, Makefile, plist)에서 실제로 `~/bin/codex`를 실행합니다. 이제 모든 `codex` 검사도 문자 그대로의 항목을 읽고 아무것도 보고하지 않는 대신 같은 방식으로 확장합니다. 그 항목의 `codex`가 `xswap-codex`에 도달하면 그 디렉터리의 일반 `codex`는 실제로 xswap을 거치므로 FAIL이 아니라 WARN으로 보고하고(무엇이 실행되는지는 디렉터리에 따라 달라집니다) `codexWrapped`는 `true`로 유지합니다 — 다만 절대 경로 항목들도 연결돼 있을 때만입니다. 이는 현재 디렉터리가 바꾸는 부분에 대한 단서일 뿐 그 자체로 판정이 아닙니다. PATH에서 래핑된 항목보다 앞에 외부 `codex`가 있거나(일반 파일은 절대 덮어쓰지 않으므로 그 우회는 영구적입니다) Codex 업데이트가 래핑된 항목을 되돌려 놓았다면, 그 항목들이 받아야 할 FAIL을 그대로 유지하고 현재 디렉터리에 대한 한 문장을 덧붙이며, `codexWrapped`는 `false`가 되고 `xswap use`/`switch`도 알림을 출력합니다 — 다른 모든 디렉터리에서는 일반 `codex`가 우회되기 때문입니다. xswap 자신도 상대 경로 `codex`를 실행하지 않습니다: 기록된 실제 Codex를 사용하거나 거부합니다. 이전 버전이 상대 경로로 기록한 `wrapper.path`(0.7.8은 조회 결과를 그대로 저장했습니다)도 작업 디렉터리 기준으로 해석하지 않습니다: `xswap doctor`는 `relative-record`와 수동 조치를 FAIL로 보고하고, `auto-disable`은 `wrapper`뿐 아니라 `wrappers`에 있는 것까지 손대지 않은 기록을 명시하며, 이제 그 기록을 지우지 않고 보존합니다. `auto-disable`이 처리하지 못한 기록(상대 경로 기록, xswap 밖에서 바뀐 항목)은 `auto.json`에 남습니다. 그 항목은 여전히 `xswap-codex`를 실행하고 있을 수 있고, 무엇으로 되돌려야 하는지를 아는 것은 그 기록뿐이기 때문입니다. 실제로 되돌린 기록은 이전과 같이 제거합니다. 같은 이유로 상대 경로가 될 수 있는 `realCodex`도 동일하게 거부합니다. 일반 `codex`와 모든 xswap 실행은 현재 디렉터리가 가진 파일을 실행하는 대신 Codex 설치가 아니라 기록이 고쳐져야 한다고 알리고, `xswap doctor`의 `real codex` 행은 그 경로를 가진 디렉터리에서만 OK를 내는 대신 어느 디렉터리에서나 같은 조치와 함께 FAIL로 보고합니다. 이름으로 조회하는 나머지 실행 파일도 같은 조회를 쓰므로 같은 규칙을 따릅니다: OpenClaw 동기화와 쿨다운 해제의 `node`·`openclaw`, 자동 데스크톱 창의 `xswap-proxy`(그 창의 `CODEX_CLI_PATH`가 됩니다), `xswap upgrade`의 `uv`·`git`·`xswap`입니다. 상대 경로 PATH 항목으로만 찾은 이름은 명령을 시작한 디렉터리의 파일을 실행하거나 오래 남는 기록에 굳히는 대신, 그 항목을 명시하며 거부합니다. `xswap alert --install`만 거부 대신 대체합니다. 상대 경로 결과를 launchd 작업에 굳히면(작업은 `/`에서 실행되므로 그 항목은 아무 의미가 없습니다) 안 되므로, 지금 실행 중인 이 프로세스의 `xswap` 실행 파일을 기록합니다. 일반 모드로 돌아가려면 `xswap auto-disable`을 실행하십시오. 이미 실행 중인 자동 세션은 계속 유지됩니다.

## 실제 Codex 실행 파일을 xswap 상태 밖에 두기

이 업데이터는 설치 위치를 `CODEX_HOME`에서 정하는데, 브리지 세션은 `CODEX_HOME`을 xswap 런타임 홈으로 두므로 세션 안에서 시작한 업데이트는 `~/.local/share/codex-swap/auto/cli-codex/packages`에 설치되어 `auto/`를 정리하면 함께 사라집니다. xswap은 자신이 소유한 홈(`auto/cli-codex`, `auto/codex`, `profiles/<이름>/codex`)의 `packages`를 기준 Codex 홈(`~/.codex` 또는 `CODEX_HOME`, 혹은 실제 Codex를 이미 보유한 등록 홈)의 `packages`로 링크해 업데이트가 원래 위치에 설치되게 하고, 실제 Codex를 그 홈 경로로 기록합니다. xswap 상태 디렉터리 안에 남아 있는 실제 Codex는 `xswap doctor`가 `real codex` FAIL로 보고하며, `xswap relocate-codex`(`--dry-run`으로 미리보기)가 릴리스를 기준 홈으로 옮기고 `current`와 `auto.json`을 다시 씁니다. 릴리스를 삭제하지 않고, 대상이 이미 있으면 거부하며, 셸 설정은 수정하지 않습니다. 일반 `codex`가 실제 Codex 실행 파일이 없다고 알리면 `xswap auto-disable` 후 Codex를 다시 설치하고 `xswap auto-enable --accounts … --wrap-codex`를 실행하십시오.
